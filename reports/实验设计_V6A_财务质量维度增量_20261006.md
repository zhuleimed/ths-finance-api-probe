# 实验设计：V6-A 财务质量维度增量

> 日期：2026-10-06 ｜ 提出：023_THS ｜ 实施目标：004_sequoia-x
> 状态：**待用户确认后实施**
> 前置：Step A 数据已采集完成（112.8 万行，2026-10-06）

---

## 1. 目的与假设

**目的**：验证同花顺新增的**财务质量维度**能否提升 004 的主指标（TOP-N 事后超额）。

**假设**：

| | 内容 |
|---|---|
| **H1** | 现金流质量维度能提升模型对"盈利真实性"的判别力 → TOP-N 超额提升 |
| **H0**（零假设） | 无提升，或提升不显著 → **不采纳，省下后续功夫** |

> **设计原则**：这是一个**能否证伪**的实验，不是一个"加上去试试"的改动。
> 跑之前就定好"什么算成功、什么算失败"，避免事后找理由。

---

## 2. 新增的 5 个维度

**全部来自 `finance_ths_v2`（今日采集）**，不改动任何现有维度。

| # | 特征名 | 来源 | 计算 | 逻辑（一句话） |
|---|---|---|---|---|
| 1 | `fin_ths_cash_quality` | `net_profit_cash_content` | 直接用 | **赚的是不是真钱**（经营现金流/净利润） |
| 2 | `fin_ths_cash_sales` | `operating_cash_flow_net_divide_income` | 直接用 | 收入的**现金转化率** |
| 3 | `fin_ths_cash_index` | `cash_operating_index` | 直接用 | 现金**回收效率** |
| 4 | `fin_ths_cash_invest` | `cash_meet_invest_ratio` | 直接用 | **内生资金**能否覆盖投资 |
| 5 | `fin_ths_rd_intensity` | 利润表 `research_and_development_expenses` | **÷ `operating_income`** | **研发投入强度** |

**为什么选这 5 个**：
- 前 4 个是 004 **完全没有**的"现金流质量"族——与现有 16 维财务特征（偏盈利/偿债/营运）**信息不重叠**
- 第 5 个（研发强度）是**成长性代理**，非量价基本面，符合待办 #8「换独立经济族」的方向

### 2.1 覆盖率（已实测，抽 400 只）

| 指标 | 2020 年后非空率 | 覆盖>80% 的股票占比 |
|---|---|---|
| 净利润现金含量 | **100%** | 99.8% |
| 销售现金比率 | **100%** | 100.0% |
| 现金营运指数 | **100%** | 99.2% |
| 现金满足投资比率 | **100%** | 99.5% |

> ✅ **不会引入"半截列"**——回测窗口（2020-08 起）**从第一天起就有覆盖**。

⚠️ **研发费用的已知限制**：只有 **50%** 的股票有值——因为**非科技公司本来就不单独披露研发费**。
这是**"公司属性的天然稀疏"，不是时间截断**，可接受；缺失按 004 惯例填 0。

## 3. ★关键设计约束（防踩坑）

### 3.1 绝不能用 `report_date_ms` 做 asof

**实测**：同花顺的 `report_date_ms`（真实披露日）**系统性晚一年**——
茅台 2023 年报真实披露 2024-04-03，接口返回 **2025**-04-03。

**必须沿用 004 现有的保守兜底** `_disclose_date()`：

```
Q1(03-31) → 当期 04-30
H1(06-30) → 当期 08-31
Q3(09-30) → 当期 10-31
年报(12-31)→ 次年 04-30
```

> 这是**防未来函数**的关键。用了接口那个字段 = 让模型提前一年看到财报，
> 回测会漂亮得离谱、实盘直接失效。

### 3.2 单位必须对齐现有口径

004 现有财务特征是**小数**（如 ROE 15.23% → `0.1523`，见 `pct_conf` 中的 `/100.0`）。

同花顺指标返回的是**百分数**（如 `15.23`）→ **新维度必须同样 `/100.0`**。

### 3.3 缺失一律填 0（与 004 惯例一致）

`_EMPTY_COLS` 模板的既有做法是 `fillna(0.0)`，新维度沿用，保证**输出列数恒定**——
否则拼接时会维度错位（这是 004 踩过的坑，见 `build_extra_features.py` 注释）。

### 3.4 不要动现有 129 维

本实验**只增不减**。待办 #6（特征瘦身）是**另一个独立实验**，不要混在一起做——
否则结果变好/变差，分不清是新维度的功劳还是瘦身的效果。

## 4. 实现位置（改哪几处）

**新增一个独立特征组 `ths_finance`**，不改任何现有组的逻辑：

| 位置 | 改动 |
|---|---|
| `build_extra_features.py` | ① 新增函数 `_ths_finance_features(code, dates)`<br>② 注册进 `FEATURE_GROUPS["ths_finance"]`<br>③ 在 `_EMPTY_COLS["ths_finance"]` 加 5 个固定列名 |
| `labels.py` | `FEATURE_VERSION` 5 → **6**（仅实验分支） |
| 数据读取 | 新增 `_load("ths_finance", code)` → 读 `data/extra_features/finance_ths_v2/` |

**不改**：`KEY_GROUPS`（关键组缺失才剔除股票；新组是可选组，缺失不剔除）。

## 5. ★开关设计（不污染生产）

**问题**：`feature_version` 在 `labels.py` 是**共享代码**。直接改会让 **11-01 的月度重训也用上新特征**——那就不是实验了。

**方案**：环境变量开关（复用 004 已有的 `V4_SAMPLE_END_FIX` 模式）

```bash
# 默认（不设此变量）= 生产行为，129 维不变
python ...

# 实验时才开
FEATURE_V6_THS_FINANCE=1 python scripts/run_shared_backtest.py ...
```

**验收标准**：不设变量时，跑出来的结果与实验前**逐位一致**（证明零影响）。

## 6. 评估方案

### 6.1 主指标（004 的标准主指标）

**TOP-N 事后超额**——不是 IC。

> 用户项目的评估纪律（待办 #12/#19）明确写着：
> *"不要只用 IC；TOP10 是更好的代理但也不是终点，最终必须看实际组合。"*

### 6.2 A/B 对照

| 臂 | 特征 | 说明 |
|---|---|---|
| **A（对照）** | 129 维 | 现有基线，结果应能与历史记录对上 |
| **B（实验）** | 134 维 | 129 + 5 新维 |

**两臂用同一套流程、同一评估脚本、同一时间窗口**（这是可比的前提）。

### 6.3 ★分段检查（防"时间坐标伪信号"）

把 70 个月分两段分别评估：

| 段 | 时间 | 含义 |
|---|---|---|
| **早期** | 2020-08 ~ 2025-08 | `news`/`dragon_tiger`/`limit_up` **无数据** |
| **近期** | 2025-09 ~ 2026-08 | 上述三维**有数据** |

**怎么读**：

| 情况 | 结论 |
|---|---|
| 两段表现接近 | ✅ 模型没学到"时间坐标"伪信号 |
| 近期明显更好 | ⚠️ 模型在靠时间作弊 → 待办 #6 需优先处理 |

> **这是零成本检查**——用现有评估脚本加个分段维度即可。

### 6.4 辅助检查（新维度本身）

| 检查 | 目的 |
|---|---|
| 新 5 维的**分布**（分位数、极端值） | 防 NaN / 离谱值进模型 |
| 新 5 维与现有 16 维财务特征的**相关性** | 若与 `fin_roe` 高度相关 → 白加，应换维度 |
| 新 5 维的**特征重要性** | 若 importance ≈ 0 → 模型没用上 |

## 7. 执行步骤与耗时

| 步 | 动作 | 耗时（实测/推算） |
|---|---|---|
| 1 | 写特征函数 + 开关 | 人工 ~1 小时 |
| 2 | **小样本验证**（10 只股票，肉眼核对值对不对） | ~10 分钟 |
| 3 | 缓存重建（129→134 维） | **~26 分钟**（实测 10-01） |
| 4 | 重训 T2/T3/T4 | **~90 分钟**（实测 10-01） |
| 5 | A/B 两臂 70 月回测 | **~30~60 分钟** |
| 6 | 分析结果 + 分段检查 | 人工 ~1 小时 |
| | **机器时间合计** | **~2.5~3 小时** |
| | **含人工（顺利）** | **约半天** |
| | **含返工缓冲** | **约 1 天** |

**为什么留缓冲**：每返工一次 = +26 分钟重建 + 90 分钟重训。

## 8. 可能失败的情形与预案

| 情形 | 预案 |
|---|---|
| 新特征算出 NaN / 极端值 | 第 2 步小样本验证就会暴露，先修再进全量 |
| 新维度与现有维度高度相关 | 换维度（如改用"现金流同比变化"而非水平值） |
| 缓存重建报显存/内存不足 | 降低 workers；参考 10-01 成功案例（12 workers 跑通） |
| 结果不显著 | **就是结论**——记录 ADR，停手，不硬凑 |
| 生产受影响 | 回滚开关（不设环境变量即回到 129 维） |

## 9. 范围边界：本实验**不做**的事

| 不做 | 原因 |
|---|---|
| ❌ 不做特征瘦身（待办 #6） | 独立实验，混一起分不清功劳 |
| ❌ 不动组合优化参数（L250 等） | 参数是对旧特征标定的，A/B 时保持一致才有可比性 |
| ❌ 不加财务三表的**原始值**（如总资产、营业收入绝对值） | 量纲太大，需先做比率派生——留给下一轮 |
| ❌ 不碰模拟盘/生产信号 | 实验只在回测层，通过开关隔离 |
| ❌ 不删 `consensus` | 那是待办 #6 的事，属另一个实验 |

## 10. 决策标准（跑之前就定好）

| 结果 | 决策 |
|---|---|
| TOP-N 超额**显著提升**（且分段检查通过） | ✅ 采纳 → 进 V6，安排排期接入生产 |
| 提升**不显著**（p > 0.05 或自助 CI 跨 0） | ❌ **不采纳**，记录结论，省下后续所有功夫 |
| 提升显著但**分段检查失败** | ⚠️ 先修伪信号问题（待办 #6），再重跑本实验 |

> **"不显著"也是有价值的结论**——它告诉你"这条路不用再花时间了"，
> 这正是 004 项目一贯的做法（方向一/二/三 都是证伪后及时止损）。
